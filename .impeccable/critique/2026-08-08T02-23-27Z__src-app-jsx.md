## Design Specificity Verdict

**LLM assessment**: Partially authored for this product. The parchment/burgundy palette and calm, tactile tone are distinctive to invite/card making — a real identity. But doc drift (DESIGN.md claims Inter-only, indigo buttons, no drag-drop; code uses Fraunces/Geist Mono, burgundy #8B3A4A, dnd-kit) and the stale audit make the surface read category-adjacent rather than category-specific.

**Deterministic scan**: detect.mjs exit 2, 4 advisory findings: font-size 16px (index.css:13) off the DESIGN.md ramp; border-radius 5px (tokens.css:172) outside the rounded scale; font-size 15px (tokens.css:282) off ramp; undocumented #000 (tokens.css:620). All technically accurate; severity advisory.

**Visual overlays** (detect.js injected, 7 anti-patterns): clipped-overflow-container on div.app-shell; low-contrast #7A6E5E on #F5F0E6 at 4.4:1 (×4) and on #E5DDD0 at 3.7:1 (×1) — real AA misses on the secondary-text token; flat-type-hierarchy (11–18px, ratio 1.6:1); cream-palette flag. The cream-palette flag is a false positive here: parchment is the intentional DESIGN.md identity.

## Overall Impression

A genuinely coherent token system — the parchment/burgundy workbench is the strongest thing here, and DOMPurify discipline is exemplary. But the core product promise (template reuse across events) is betrayed by save/resume dropping CSV state, the batch-render payoff is invisible in Preview, and the secondary-text token fails AA on two of its own surfaces. The single biggest opportunity: make save/resume and the batch preview honor the template-as-asset positioning.

## What's Working

1. **Token-backed CSS with dark mode + reduced motion** — tokens.css is systematic, custom-property-only, and respects both prefers-color-scheme and prefers-reduced-motion with zero JS.
2. **DOMPurify end-to-end** — Preview sanitizes substituted CSV values and image sources; "sanitize everything" is enforced in code, not just PRODUCT.md.
3. **Content-forward two-pane workbench** — the live preview column keeps the user's output central; the aesthetic is distinctive without decoration.

## Priority Issues

### [P0] Save/resume silently drops CSV state and mapping
- **What**: saveTemplate (Toolbar.jsx:15-27) serializes only version/blocks/tags/images; loadTemplate (44-47) hydrates only those. csvRows, csvHeaders, csvMapping, renderResults, renderErrors are lost on reload.
- **Why it matters**: Directly violates the PRODUCT.md core promise — "a finished composition serializes to a single .cadence.json that can be re-uploaded and resumed." Template reuse across events is the positioning; this breaks it. Jordan (first-timer) saves, reloads, and loses all CSV work.
- **Fix**: Extend payload to version 2 with csvRows/csvMapping (+ render state), migrate v1→v2 on load.

### [P0] Preview shows only the first batch-rendered row
- **What**: Preview.jsx:13 returns renderResults[0].html exclusively; rows 2..N are unverifiable in the preview pane.
- **Why it matters**: The batch-render peak ("watch personalized output materialize") is capped at row 1; users must download/print each row to verify. Riley can't spot row-level failures without drilling into details.
- **Fix**: Add a row stepper/selector to Preview when renderResults.length > 0; surface row errors inline.

### [P1] Secondary-text token fails WCAG AA on its own surfaces
- **What**: Detector measured #7A6E5E on #F5F0E6 = 4.4:1 (×4 instances) and on #E5DDD0 = 3.7:1 (×1) — under the 4.5:1 AA threshold. DESIGN.md claims all interactive components pass AA.
- **Why it matters**: Muted labels (section eyebrows, hints, counts) fail contrast for low-vision users; the design doc's AA claim is false for the most-used text role.
- **Fix**: Darken --color-text-secondary at token level (e.g. #6B5F50) and re-check both surfaces.

### [P1] DESIGN.md contradicts the implementation
- **What**: DESIGN.md says Inter is the sole typeface, buttons use "solid indigo fill", reorder is "up/down controls, no drag-drop". Code: Fraunces/Inter/Geist Mono/Atkinson, burgundy #8B3A4A, dnd-kit drag-and-drop. Detector's 4 advisory findings are all consequences of this drift.
- **Why it matters**: The design record is untrusted; future contributors will be misled; detector noise compounds.
- **Fix**: Align DESIGN.md with the actual token system (or $impeccable document to regenerate from code).

### [P1] ErrorBoundary imported but never mounted
- **What**: App.jsx imports ErrorBoundary (line 7) but the JSX never uses it.
- **Why it matters**: Any uncaught React error in any component blanks the entire SPA with no fallback UI — data-loss risk for a client-side-only tool.
- **Fix**: Mount <ErrorBoundary> around the content split.

### [P1] Render all blocks the main thread silently
- **What**: renderAll (Toolbar.jsx:59) is a synchronous for-loop over all CSV rows with no progress, no cancel, no chunking.
- **Why it matters**: Riley uploads a 10,000-row CSV and the UI freezes with zero feedback; no way to abort.
- **Fix**: Chunk the loop (yield to event loop every N rows), show progress, allow cancel.

## Persona Red Flags

**Jordan (first-timer)**: Lands on "Paste HTML with {{tag}} placeholders..." with no explanation of what {{tag}} means or how it connects to CSV/images. Adds a block, sees Tags populate, never understands the data flow. Clicks Save, reloads, loses all CSV work — the core promise becomes a trap. No undo anywhere; a misclick deletes a block permanently.

**Sam (accessibility)**: Tab switcher lacks role="tab"/aria-selected. Secondary-text labels at 4.4:1/3.7:1 fail AA. "Unmapped tags" renders in error-red and reads as an error to screen readers even when intentionally unmapped. Draft textarea has a placeholder but no visible label.

**Riley (stress tester)**: 20 URL images each 50MB show "0.0MB used" — the counter tracks only base64 bytes. 10k-row CSV freezes the app on Render all. Papa.parse has no error callback, so malformed CSVs fail silently or throw uncaught. Load failure is a raw alert().

## Minor Observations

- Draft length counter is noise, not signal (BlockComposer.jsx:140).
- Preview empty state uses inline styles (padding: '24px 0', fontSize: 15) bypassing tokens.
- Toolbar hardcodes filenames (cadence.json, cadence-export.zip) with no user control.
- Header pairs a mono uppercase eyebrow with an italic Fraunces title — DESIGN.md bans "unnecessary visual chatter".
- DnD (dnd-kit) duplicates the up/down buttons and contradicts the original plan's adversarial decision #6 ("zero drag-drop dependency"). Buttons carry both onClick and drag listeners — odd hybrid.
- Tab switcher is visible on desktop where both panes are always shown — dead control at ≥768px.

## Questions to Consider

- If the template is the primary asset, why is CSV mapping — the bridge between template and data — treated as secondary state that isn't saved?
- Why does Preview default to rendering with empty mapping values instead of showing raw {{tag}} syntax so users can verify placeholders before committing data?
- Does keeping both up/down buttons AND dnd-kit earn its complexity, or is one drag path enough?
